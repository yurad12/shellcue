# ShellCue 로컬 백로그

GitHub Issues를 사용하기 전까지 이 문서를 로컬 작업 보드로 사용한다. 한 번에 `진행 중` 작업은 하나만 둔다.

## 진행 중

- `SPIKE-004` 세션 이동과 이름·메모 재연결 안정화
  - Terminal의 탭 위치 대신 TTY·프로세스 ID·시작 시점으로 식별
  - 이동 직전 세션 수명 확인 및 현재 탭 검색
  - 기존 iTerm 메모 키 유지, 구형 Terminal 메모는 원본 보존
  - 단위 테스트와 실제 탭 이동·재실행 검증

## 검증 대기

- 메모 입력 오류 수정: TextEditor와 포커스를 유지하는 메뉴 막대 팝오버 적용
  - Enter/Shift-Enter 줄바꿈, 이름·메모 이모지 입력, 저장 후 재열기 확인 필요
  - 편집이 별도 창 없이 패널 안에서 이어지고 이모지 선택 중 입력이 유지되는지 확인 필요

- `APP-003` 작업 경로를 기준으로 프로젝트 그룹과 정렬 제공
  - 가장 가까운 Git 루트 감지
  - Git 외 경로는 현재 폴더 기준으로 그룹 생성
  - B 시안 기반의 컴팩트 프로젝트 헤더와 세션 묶음 적용
  - 이름 → 메모/명령 → 상태 순으로 정보 위계 정리
  - 실제 Terminal/iTerm 혼합 환경 수동 검증 필요

## 다음 — 사용자 불편을 줄이는 순서

작업마다 불편과 완료 조건을 기준으로 검증한다. 아래 순서는 제안 우선순위이며, 실제 사용자 검증에 따라 조정한다.

1. `APP-005` 원하는 세션까지 가는 조작 줄이기
   - 불편: 메뉴 막대를 열고 목록을 훑고 클릭하는 동작이 반복된다.
   - 범위: 전역 단축키, 검색 자동 포커스, 방향키·Enter·Esc, 안정적인 목록 순서.
   - 완료: 마우스 없이 세션으로 이동하고, 갱신 중에도 선택 대상이 바뀌지 않는다. 8~12개 세션에서 기존 방식과 탐색 시간을 비교한다.
2. `APP-006` 같은 프로젝트의 세션 구분 개선
   - 불편: 세션 번호와 동일한 폴더명만으로는 작업을 구분하기 어렵다.
   - 범위: 용도를 우선 표시하고 짧은 경로·명령을 보조 표시. 브랜치·worktree 표시는 구분에 필요한 경우 추가한다.
   - 완료: 같은 저장소의 서버·로그·작업 세션을 구별할 수 있고, 상태 변경으로 행이 이동하지 않는다.
3. `APP-007` 작업을 이어가기 위한 메모 사용 검증
   - 불편: 세션으로 돌아와도 다음에 할 일을 잊는다.
   - 범위: 이름·메모 편집 진입 단축, 저장 실패 시 입력 보존, 메모 미리보기 문구와 실제 표시 일치.
   - 완료: 다른 작업 후 복귀하는 과제로 검증하고, 사용자가 자발적으로 메모를 남기는지 확인한 뒤 확장 여부를 정한다.

## 배포 전

- `DIST-001` 설치와 첫 연결 과정 검증
  - 불편: 다운로드 후 앱이 실행됐는지, 왜 터미널이 안 보이는지 알기 어렵다.
  - 범위: 첫 실행 안내, 메뉴 막대 위치 안내, 서명·공증과 설치 패키지.
  - 완료: 개발 환경이 없는 별도 Mac에서 설치부터 첫 세션 이동까지 검증한다. 서명·공증에는 개발자 계정 준비가 필요하다.
