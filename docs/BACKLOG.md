# 다음에 할 일

먼저 매일 쓰면서 걸리는 부분을 다듬고, 그다음 원하는 세션까지 가는 조작을 줄인다. 한 번에 한 묶음씩 진행한다.

자동 테스트는 당분간 두지 않는다. 변경 후 빌드하고 실제 앱에서 확인한다.

## 먼저: 패널과 메모 편집

인라인 편집을 유지하면서 Esc·외부 클릭으로 닫기, 이동 성공 후 닫기, 두 줄 메모 미리보기를 구현했다. 초안은 앱 상태에 두어 패널을 닫아도 유지한다. 저장하거나 취소하면 편집을 마친다. 앱을 종료하면 미저장 초안은 사라진다.

앱 실행은 확인했지만 화면 제어 연결이 시간 초과되어 아래 동작은 직접 확인이 남아 있다.

- 이름과 메모에서 이모지 선택창을 클릭해도 패널이 닫히지 않고 입력되는지
- Enter·Shift-Enter 줄바꿈과 저장 후 두 줄 미리보기가 맞는지
- Esc·외부 클릭·아이콘 재클릭으로 닫았다 열어도 편집 내용이 그대로 남는지
- 취소는 초안만 버리고, 터미널 이동은 성공했을 때만 패널을 닫는지

이전 패널 수정의 수동 확인 항목은 아직 남아 있다.

## 이어서: 키보드로 세션 이동

`⌃⌥Space`로 패널 열기·닫기, 검색창 자동 포커스, ↑·↓ 선택, Enter 이동을 구현했다. 검색 결과의 선택 행을 강조하고 화면 밖으로 내려가면 스크롤한다. 목록을 다시 열면 검색을 비우며, 미저장 메모가 있으면 편집을 이어간다.

살아 있는 세션은 기존 순서를 유지하고 새 세션은 그룹 뒤에 추가한다. 선택은 세션 ID로 유지한다. 선택한 세션이 닫히면 Enter가 다른 세션으로 이동하지 않게 했다.

화면 제어 권한이 없어 새 버전의 실제 키 입력 확인은 남아 있다. 실행 중인 이전 앱은 초안이 있을 수 있어 강제로 종료하지 않았다. 저장 후 종료하고 `swift run ShellCue`로 다시 실행해 다음을 확인한다.

- 다른 앱에서 단축키로 열고 검색창에 바로 입력할 수 있는지
- 8~12개 세션에서 ↑·↓로 선택한 행이 보이고 Enter로 정확한 곳에 이동하는지
- 검색창의 한글 조합·후보 선택과 메모의 줄바꿈에 방향키·Enter가 간섭하지 않는지
- Esc로 닫았다가 단축키로 다시 열 수 있는지

## 그다음: 구분하기 쉬운 목록과 빠른 응답

- 같은 프로젝트의 세션을 이름, 짧은 경로, 실행 명령으로 구분하기 쉽게 만든다. 브랜치나 worktree는 실제 구분에 도움이 될 때 추가한다.
- 이름이나 상태가 바뀌어도 행이 불필요하게 움직이지 않게 한다.
- 세션 검색과 프로세스 조회가 화면 처리를 막는지 확인한다. 세션이 많아도 검색·메모 입력이 끊기지 않게 개선한다.

## 실제 터미널에서 확인할 것

실제 사용 환경에서 확인할 항목이다.

- Terminal과 iTerm2를 함께 열었을 때 프로젝트 그룹과 상태가 맞는지
- 탭을 옮기거나 앱을 다시 실행해도 이름과 메모가 같은 세션에 붙는지
- 닫힌 세션이나 재사용된 TTY에 예전 메모가 잘못 붙지 않는지
- 한쪽 터미널의 권한이 없어도 다른 쪽 목록과 이동은 작동하는지

구형 Terminal 메모는 파일에 보존되어 있지만 세션 수명을 확인할 정보가 없어 자동으로 옮기지 않는다. iTerm 메모는 기존 세션 ID를 그대로 쓴다.

## 다른 사람에게 배포하기 전

버전을 빌드마다 구분하고, ZIP을 받은 사람이 설치부터 권한 허용·첫 세션 이동까지 진행해 본다. 개발 환경이 없는 별도 Mac에서도 확인한다. Developer ID 서명과 Apple 공증도 준비한다.

최근 닫힌 세션, AI 도구별 상태, 추가 터미널 지원은 위 작업을 마친 뒤 필요를 보고 결정한다.

## 단축키 복구 확인

누락된 `KeyboardSupport.swift`를 복구했다. 새 캐시 경로에서 `swift build`를 통과했다. 실제 전역 키 입력은 아직 확인하지 않았다. 기존 앱을 종료한 다음 새 빌드로 실행해 다른 앱에서 ⌃⌥Space, 검색, ↑·↓, Enter, Esc를 확인한다. 사용자 지정 키 설정은 기본 단축키 검증 후 검토한다.

## VS Code 연결 실험

- 로컬 macOS 전용 연결 확장과 VSCodeAdapter 초안 구현. JavaScript 구문 검사와 Swift 빌드 통과.
- 사용자 전용 폴더의 파일 통신을 우선 사용. 비동기 소켓 통신으로 바꿔 포커스 응답 대기가 UI를 막지 않도록 개선 필요.
- 실제 앱 검증 미완료: VS Code 창 두 개, 같은 이름의 탭, 분할 터미널에서 정확한 이동·창 활성화 확인 필요.
- 창 종료와 확장 중지 시 4초 이내 목록 제외, 대상 탭 삭제 시 오류, Terminal/iTerm 동시 사용 확인 필요.
- reload/restart 후 이름·메모 재연결은 지원하지 않음. 새로운 ID를 임의로 기존 세션에 붙이지 않는다.
- 배포용 VSIX 포장과 일반 설치는 실제 연결 검증 후 진행.
