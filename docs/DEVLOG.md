# ShellCue 개발 일지

## 2026-09-24

### 메모 줄바꿈과 이모지 입력 수정

- 메모의 다중 행 TextField를 TextEditor로 교체했다. 저장 단축키는 Command-S로 유지한다.
- 별도 편집창은 편집 흐름을 번거롭게 만들어 제거하고 메뉴 막대 패널 안의 인라인 편집으로 되돌렸다.
- SwiftUI MenuBarExtra 대신 앱이 제어하는 메뉴 막대 팝오버를 사용한다. 이모지 선택창으로 포커스가 이동해도 팝오버와 입력 내용을 유지하고, 메뉴 막대 아이콘을 다시 누르면 닫는다.
- 저장·재로드 테스트에 여러 줄, 빈 줄, 복합 이모지를 포함했다. 실제 Enter/Shift-Enter 및 시스템 이모지 선택창 동작은 화면 자동화 권한이 없어 수동 검증이 필요하다.

### swift run 자동화 권한 재발 수정

- TCC 로그에서 SwiftPM 직접 실행의 권한 요청자가 ShellCue가 아닌 VS Code로 귀속되고, VS Code의 `NSAppleEventsUsageDescription` 부재로 거부되는 것을 확인했다. 실행 파일에 plist를 넣는 것만으로는 해결되지 않았다.
- `swift run`은 개발용 `ShellCue.app`을 구성·임시 서명한 뒤 Launch Services로 실행한다. 이미 실행 중이면 중복 실행하지 않으며, 새 빌드 적용은 앱 메뉴에서 종료 후 다시 실행한다. 실행 명령은 앱을 연 뒤 반환한다.
- `swift run ShellCue --diagnose`로 앱 번들에서 연결을 진단할 수 있다. 결과는 빌드 폴더의 `shellcue-diagnostics.log`에 기록한다. 진단 전 실행 중인 앱을 종료해야 한다.
- 단위 테스트 20개 통과. 실제 TCC 요청자가 `com.shellcue.app`으로 바뀌었고, 앱 번들 진단에서 iTerm2 세션 1개를 검색했다. Terminal은 열린 세션이 없어 0개였다.
- 수정된 일반 앱도 실행했다. 화면 자동 확인 권한이 없어 최종 목록 표시와 클릭 이동은 사용자 확인이 필요하다.
- 개발용 임시 서명은 정식 배포 서명이 아니며, 바이너리 변경 후 권한 재승인이 필요할 수 있다. README에는 진행 기록을 추가하지 않았다.

### AI 작업 구조와 세션 재연결 안정화

- 짧은 공통 지침을 `harness.md`에서 `AGENTS.md`로 통합했다. Claude용 파일은 만들지 않는다.
- Terminal 세션 키를 창·탭 번호에서 TTY와 루트 프로세스 PID·시작 시점으로 변경했다. 식별이 불확실하면 저장과 포커스를 거부한다.
- Terminal 이동 시 세션 수명을 다시 확인하고 현재 TTY의 탭을 찾는다. iTerm은 기존 세션 ID를 유지하며, 닫힌 대상을 성공으로 처리하지 않는다.
- 저장 실패 시 메모 편집 화면과 입력을 유지하고, 저장 성공 후에만 메모리 상태를 갱신한다.
- 구형 Terminal 메모는 JSON에 보존하지만 수명 정보가 없어 자동 이관하지 않는다. iTerm 메모 키는 그대로 유지한다.
- 탭 위치 변경, 포그라운드 명령 변경, TTY/PID 재사용, 불확실한 식별 및 메모 저장·재로드 회귀 테스트를 추가했다.
- 실제 GUI에서 탭 이동·닫기와 앱 재실행 검증은 남아 있다. `SPIKE-004`는 진행 중으로 유지한다.

### 실행 및 작업 환경 점검

- 전체 13개 단위 테스트와 release 앱 패키징을 다시 확인했다.
- 생성된 앱의 임시 서명 검증과 실제 메뉴 막대 등록, 프로세스 유지를 확인했다.
- SwiftPM 실행 파일에도 Apple Events 사용 설명과 안정적인 번들 식별자를 포함했다.
- 터미널별 연결 오류를 격리해 한쪽 권한 실패가 다른 쪽의 세션을 숨기지 않게 했다.
- 자동화 권한이 없을 때 빈 목록 대신 원인과 시스템 설정 이동 버튼을 표시한다.
- VS Code launch 설정에 남아 있던 잘못된 workspace 이름을 저장소 루트로 수정했다.
- 프로젝트의 핵심 원칙과 작업 기준만 `harness.md`에 정리했다.

## 2026-09-22

### 결정

- 제품명을 ShellCue로 확정했다.
- GitHub 연결 전에는 `docs/BACKLOG.md`를 로컬 작업 보드로 사용한다.
- Swift Package 안에 코어 라이브러리, 메뉴 막대 실행 파일, 테스트 타깃을 분리했다.

### 구현

- SwiftUI `MenuBarExtra` 기반 메뉴 막대 목록
- Terminal 탭 발견 어댑터
- iTerm2 세션 및 분할 pane 발견 어댑터
- Terminal/iTerm2 포커스 이동
- AppleScript 레코드 파서와 단위 테스트 초안

### 실환경 검증

- iTerm2에서 세션 ID, TTY, 세션 이름, 처리 상태, 프롬프트 상태를 읽었다.
- 읽은 iTerm2 세션 ID를 이용해 해당 세션으로 포커스 이동했다.
- Terminal을 테스트용으로 실행해 창 ID, TTY, busy 상태를 읽었다.
- 선택한 Terminal 탭으로 포커스한 뒤, 테스트 전 실행 중이 아니었던 Terminal을 종료했다.

### 장애물

- 설치된 Command Line Tools의 Swift 컴파일러는 6.3.3이고 SDK Swift 인터페이스는 6.3.2여서 전체 빌드가 실패한다.
- Xcode 전체 앱이 설치되어 있지 않다.
- 모든 Swift 파일의 구문 파싱은 통과했다. 타입 검사, 링크, 테스트 실행은 호환되는 Xcode 설치 후 다시 수행해야 한다.

### iTerm 상태 판정 보완

- iTerm의 `is processing`과 `is at shell prompt`가 모두 `false`인 환경을 확인했다.
- TTY의 포그라운드 프로세스를 읽어 입력 대기와 실행 중을 판정하는 보조 경로를 추가했다.
- `kiro-cli-term`처럼 내부 TTY를 만드는 터미널도 부모·자식 프로세스를 따라 상태를 판정한다.
- 상태 판정 테스트를 추가했고 전체 7개 테스트가 통과했다.

### 용도와 다음 할 일

- 세션 행에 편집 버튼과 전용 편집 화면을 추가했다.
- 사용자가 지정한 용도를 기본 터미널 제목보다 우선 표시한다.
- 다음 할 일을 목록에 함께 표시하고 두 필드를 검색 대상으로 포함했다.
- 메타데이터를 Application Support의 JSON 파일에 원자적으로 저장한다.
- 저장소 테스트를 추가했고 전체 9개 테스트가 통과했다.
- 사용자 확인을 반영해 다음 할 일을 여러 줄 메모로 확장하고 목록 미리보기는 두 줄로 제한했다.
- 여러 줄 입력과 충돌하지 않도록 저장 단축키를 Return에서 Command-S로 바꿨다.
- Kiro가 동일한 형태의 터미널 제목을 만드는 경우 이름 지정 전 세션을 구분하기 어렵다는 점을 확인했다.
- 중첩 TTY의 프로세스 트리를 따라 실제 작업 폴더와 실행 명령을 수집한다.
- 사용자 용도가 없으면 `폴더 · 명령` 또는 `폴더 · TTY 번호`를 임시 이름으로 표시한다.

### zsh 이벤트 스파이크

- 현재 셸에서 수동으로 source할 수 있는 zsh hook을 추가했다.
- 명령 전문 대신 첫 실행 파일 이름만 로컬 이벤트에 기록한다.
- 명령 시작, 종료 코드, 경로 변경, 셸 종료 이벤트를 NUL 구분 파일로 전달한다.
- Kiro 내부 TTY 이벤트를 바깥 iTerm 세션과 연결한다.
- 메뉴 패널이 열려 있는 동안 2초마다 상태를 갱신한다.
- 대화형 zsh에서 `sleep`, `false`, `cd` 이벤트 생성을 확인했다.
- 전체 13개 단위 테스트가 통과했다.

### zsh 이벤트 기능 제거

- 수동 source와 추후 설치 과정에 비해 최근 성공·오류 상태의 가치가 분명하지 않다는 사용자 피드백을 반영했다.
- zsh hook, 이벤트 파일, 파서, 최근 성공·오류 상태를 MVP에서 제거했다.
- 별도 설치가 필요 없는 프로세스 기반 실행 중·입력 대기 판정과 2초 자동 갱신은 유지한다.

### 프로젝트 그룹

- 작업 경로에서 가장 가까운 `.git` 디렉터리 또는 worktree 마커를 찾아 프로젝트 루트로 사용한다.
- Git 저장소 밖에서는 현재 작업 폴더를 그룹으로 사용한다.
- 프로젝트 섹션에 이름, Git 여부, 열린 세션 수를 표시한다.
- 자동 세션 이름은 TTY 번호를 사용해 실행 명령이 바뀌어도 행 순서가 유지된다.
- 전체 13개 테스트가 통과했다.
- macOS에서 여러 줄 TextEditor의 테두리가 한글 첫 줄과 겹치는 문제를 시스템 다중 행 TextField로 교체해 수정했다.
- UI 비교 시안 중 B 컴팩트 목록을 기반으로 프로젝트 헤더와 세션 행을 다시 구성했다.
- 기본 List 구분선을 제거하고 프로젝트별 둥근 세션 묶음, 상태 점, 한 줄 메모 미리보기를 적용했다.
