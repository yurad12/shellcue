# ShellCue 개발 일지

## 2026-09-22

### 결정

- 제품명을 ShellCue로 확정했다.
- GitHub 연결 전에는 `docs/BACKLOG.md`를 로컬 작업 보드로 사용한다.
- Swift Package 안에 코어 라이브러리, 메뉴 막대 실행 파일, 테스트 타깃을 분리했다.

### 구현

- SwiftUI `MenuBarExtra` 기반 메뉴 막대 목록
- Terminal 탭 발견 어댑터
- iTerm2 세션 및 분할 pane 발견 어댑터
- Terminal/iTerm2 포커스 이동
- AppleScript 레코드 파서와 단위 테스트 초안

### 실환경 검증

- iTerm2에서 세션 ID, TTY, 세션 이름, 처리 상태, 프롬프트 상태를 읽었다.
- 읽은 iTerm2 세션 ID를 이용해 해당 세션으로 포커스 이동했다.
- Terminal을 테스트용으로 실행해 창 ID, TTY, busy 상태를 읽었다.
- 선택한 Terminal 탭으로 포커스한 뒤, 테스트 전 실행 중이 아니었던 Terminal을 종료했다.

### 장애물

- 설치된 Command Line Tools의 Swift 컴파일러는 6.3.3이고 SDK Swift 인터페이스는 6.3.2여서 전체 빌드가 실패한다.
- Xcode 전체 앱이 설치되어 있지 않다.
- 모든 Swift 파일의 구문 파싱은 통과했다. 타입 검사, 링크, 테스트 실행은 호환되는 Xcode 설치 후 다시 수행해야 한다.

### 다음 작업

1. 호환되는 Xcode 설치 후 `swift build`와 `swift test` 실행
2. 메뉴 막대 앱을 실행해 두 터미널의 동시 목록 표시 확인
3. zsh 이벤트 수집기 구현

## 2026-09-23

### 개발 환경 복구

- Xcode 26.6을 활성 개발 도구로 선택하고 라이선스 및 초기 설정을 완료했다.
- 단위 테스트를 XCTest 기반으로 전환했다.
- `swift build`와 `swift test` 실행을 확인했다.

### 다음 작업

1. `swift run ShellCue`로 메뉴 막대 앱 수동 검증
2. Terminal과 iTerm2 세션 목록, 상태, 포커스 이동 확인
3. 발견한 문제를 수정한 뒤 `SPIKE-001` 완료 처리

### iTerm 상태 판정 보완

- iTerm의 `is processing`과 `is at shell prompt`가 모두 `false`인 환경을 확인했다.
- TTY의 포그라운드 프로세스를 읽어 입력 대기와 실행 중을 판정하는 보조 경로를 추가했다.
- `kiro-cli-term`처럼 내부 TTY를 만드는 터미널도 부모·자식 프로세스를 따라 상태를 판정한다.
- 상태 판정 테스트를 추가했고 전체 7개 테스트가 통과했다.

### 용도와 다음 할 일

- 세션 행에 편집 버튼과 전용 편집 화면을 추가했다.
- 사용자가 지정한 용도를 기본 터미널 제목보다 우선 표시한다.
- 다음 할 일을 목록에 함께 표시하고 두 필드를 검색 대상으로 포함했다.
- 메타데이터를 Application Support의 JSON 파일에 원자적으로 저장한다.
- 저장소 테스트를 추가했고 전체 9개 테스트가 통과했다.
- 사용자 확인을 반영해 다음 할 일을 여러 줄 메모로 확장하고 목록 미리보기는 두 줄로 제한했다.
- 여러 줄 입력과 충돌하지 않도록 저장 단축키를 Return에서 Command-S로 바꿨다.
- Kiro가 동일한 형태의 터미널 제목을 만드는 경우 이름 지정 전 세션을 구분하기 어렵다는 점을 확인했다.
- 중첩 TTY의 프로세스 트리를 따라 실제 작업 폴더와 실행 명령을 수집한다.
- 사용자 용도가 없으면 `폴더 · 명령` 또는 `폴더 · TTY 번호`를 임시 이름으로 표시한다.

### zsh 이벤트 스파이크

- 현재 셸에서 수동으로 source할 수 있는 zsh hook을 추가했다.
- 명령 전문 대신 첫 실행 파일 이름만 로컬 이벤트에 기록한다.
- 명령 시작, 종료 코드, 경로 변경, 셸 종료 이벤트를 NUL 구분 파일로 전달한다.
- Kiro 내부 TTY 이벤트를 바깥 iTerm 세션과 연결한다.
- 메뉴 패널이 열려 있는 동안 2초마다 상태를 갱신한다.
- 대화형 zsh에서 `sleep`, `false`, `cd` 이벤트 생성을 확인했다.
- 전체 13개 단위 테스트가 통과했다.

### zsh 이벤트 기능 제거

- 수동 source와 추후 설치 과정에 비해 최근 성공·오류 상태의 가치가 분명하지 않다는 사용자 피드백을 반영했다.
- zsh hook, 이벤트 파일, 파서, 최근 성공·오류 상태를 MVP에서 제거했다.
- 별도 설치가 필요 없는 프로세스 기반 실행 중·입력 대기 판정과 2초 자동 갱신은 유지한다.

### 프로젝트 그룹

- 작업 경로에서 가장 가까운 `.git` 디렉터리 또는 worktree 마커를 찾아 프로젝트 루트로 사용한다.
- Git 저장소 밖에서는 현재 작업 폴더를 그룹으로 사용한다.
- 프로젝트 섹션에 이름, Git 여부, 열린 세션 수를 표시한다.
- 자동 세션 이름은 TTY 번호를 사용해 실행 명령이 바뀌어도 행 순서가 유지된다.
- 전체 13개 테스트가 통과했다.
- macOS에서 여러 줄 TextEditor의 테두리가 한글 첫 줄과 겹치는 문제를 시스템 다중 행 TextField로 교체해 수정했다.
- UI 비교 시안 중 B 컴팩트 목록을 기반으로 프로젝트 헤더와 세션 행을 다시 구성했다.
- 기본 List 구분선을 제거하고 프로젝트별 둥근 세션 묶음, 상태 점, 한 줄 메모 미리보기를 적용했다.
