# ShellCue 제품 기획서

문서 상태: MVP 기획안  
작성일: 2026-09-22  
제품명: ShellCue

## 1. 제품 개요

ShellCue는 macOS Terminal과 iTerm2에서 실행 중인 세션을 자동으로 모아 보여주는 메뉴 막대 앱이다. 사용자는 각 세션에 `프론트 서버`, `Docker 로그`, `커밋·푸시` 같은 용도 이름과 다음 할 일을 기록할 수 있다. 목록에서 항목을 누르면 원래 터미널 창과 탭으로 돌아간다.

ShellCue는 새로운 터미널 에뮬레이터가 아니다. 사용자가 평소 사용하는 Terminal과 iTerm2 위에 얹히는 작업 인덱스다.

### 제품 약속

> 다른 일을 하다가 돌아와도, 어느 터미널에서 무엇을 하던 중이었는지 5초 안에 찾는다.

## 2. 해결하려는 문제

개발자는 한 프로젝트에서도 서로 다른 터미널을 사용한다.

- Docker나 데이터베이스를 실행하는 터미널
- 프론트엔드 또는 API 서버를 실행하는 터미널
- 로그를 지켜보는 터미널
- AI 코딩 도구를 사용하는 터미널
- Git 커밋과 푸시를 수행하는 터미널

탭 제목은 `zsh`, 폴더명, 현재 실행 중인 프로세스로 자주 바뀐다. 같은 프로젝트 폴더를 사용하는 세션도 많아서 경로만으로 용도를 구분하기 어렵다. 사용자는 각 창을 열어보고 출력을 읽은 다음에야 무엇을 하던 곳인지 기억한다.

기존 제품은 세션 목록, 그룹, 실행 상태, 메모 중 일부를 제공한다. ShellCue는 프로젝트별 프로필을 미리 만들지 않아도 이 기능들을 한 흐름으로 연결하는 데 초점을 둔다. 터미널 제어를 위한 macOS 권한 외에 별도 셸 설치를 요구하지 않는다.

1. 이미 열려 있는 세션을 발견한다.
2. 세션의 용도를 사용자가 기억하기 쉬운 이름으로 유지한다.
3. 현재 상태와 마지막 명령 결과를 보여준다.
4. 다음에 할 일을 세션에 붙여둔다.
5. 한 번에 원래 위치로 돌아간다.

## 3. 목표 사용자

MVP의 주 사용자는 다음 조건에 해당하는 macOS 개발자다.

- Terminal 또는 iTerm2를 사용한다.
- 동시에 5개 이상의 터미널 세션을 자주 연다.
- 서버, Docker, 로그, Git, AI 도구가 섞인 로컬 개발을 한다.
- tmux 중심의 고정된 세션 관리 체계를 사용하지 않는다.

초기 지원 대상에서 SSH 내부 세션, tmux 내부 pane, 원격 서버 상태는 제외한다. Terminal이나 iTerm2 탭 안에서 SSH를 사용한 경우 세션 자체는 보일 수 있지만, 원격 명령 상태를 정확하게 지원한다고 약속하지 않는다.

## 4. 핵심 개념

### 4.1 세션

명령을 입력하고 실행할 수 있는 최소 단위다.

- macOS Terminal: 탭
- iTerm2: 세션. 분할 pane 하나가 세션 하나다.

창이나 프로젝트가 아니라 세션을 관리 단위로 삼는다. 같은 창 안에서도 Docker, 서버, Git의 용도가 다를 수 있기 때문이다.

### 4.2 용도

사용자가 이 세션을 왜 열어두었는지 나타내는 지속적인 이름이다. 현재 실행 명령과 분리해서 저장한다.

예시:

- 프론트 개발 서버
- 결제 오류 로그
- 커밋 · 푸시
- 로그인 화면 수정

사용자가 직접 정한 용도는 자동 추정으로 덮어쓰지 않는다. `git push` 후 `ls`를 실행해도 `커밋 · 푸시`라는 이름은 유지한다.

### 4.3 상태

관측 가능한 실행 상태다.

| 상태 | 의미 |
|---|---|
| 입력 대기 | 셸이 포그라운드에서 다음 명령을 받을 수 있음 |
| 실행 중 | 셸 외의 포그라운드 프로세스가 실행 중임 |
| 연결 확인 필요 | 셸 연동 또는 터미널 연결이 끊겨 현재 상태를 확정할 수 없음 |

`실행 중`은 해당 서비스가 정상이라는 뜻이 아니다. 출력이 멈췄다고 완료로 판단하지 않는다. AI 승인 대기처럼 도구별 이벤트가 필요한 상태는 MVP 이후 별도 연동으로 제공한다.

### 4.4 다음 할 일

사용자가 해당 세션으로 돌아왔을 때 이어서 할 행동을 적는 짧은 메모다.

예시:

- 모바일 로그인 확인 후 커밋
- 오류 재현되면 API 로그 저장
- 리뷰 반영하고 다시 push

자유 형식의 짧은 여러 줄 메모를 기본으로 한다. 목록에서는 최대 두 줄만 미리 보여주고 편집 화면에서 전체 내용을 확인한다. 별도의 체크리스트 모델, 문서 편집기, 프로젝트 전체 할 일 관리로 확장하지 않는다.

## 5. 사용자 경험

### 5.1 첫 실행

1. ShellCue를 실행한다.
2. Terminal과 iTerm2 중 설치되어 있거나 실행 중인 앱을 자동으로 감지한다.
3. 터미널 제어를 위한 macOS 자동화 권한을 안내한다.
4. 발견한 세션이 목록에 나타난다.

목록과 이름·메모 기능은 가능한 범위에서 먼저 보여주고, 상태 연동이 없으면 `상태 연결 필요`로 표시한다. 설정이 끝난 것처럼 숨기지 않는다.

### 5.2 일상 사용

1. 사용자가 평소처럼 Terminal 또는 iTerm2를 연다.
2. ShellCue가 TTY와 터미널 어댑터 정보를 연결해 목록에 추가한다.
3. 사용자가 자동 제안된 이름을 그대로 쓰거나 수정한다.
4. 필요한 경우 다음 할 일을 기록한다.
5. 메뉴 막대 목록에서 세션을 선택해 원래 터미널로 이동한다.

### 5.3 세션 종료

열린 세션이 사라지면 바로 삭제하지 않고 `최근 닫힘`에 짧게 보관한다. MVP 기본 보관 기간은 24시간으로 제안하며 사용자 테스트 후 조정한다.

최근 닫힌 항목에는 용도, 메모, 프로젝트, 마지막 결과만 남긴다. 닫힌 프로세스나 스크롤백을 복구한다고 약속하지 않는다.

## 6. 화면 구조

### 6.1 메뉴 막대 패널

패널은 검색과 세션 목록을 중심으로 한다. 통계 카드, CPU 그래프, 터미널 화면 미리보기는 MVP에서 제외한다.

```text
ShellCue                               확인 필요 1
┌──────────────────────────────────────────────┐
│ 프로젝트, 용도, 명령 검색                    │
└──────────────────────────────────────────────┘

storefront · feat/login

● 프론트 개발 서버                  실행 중 42분
  npm run dev · localhost:3000
  다음: 모바일 화면 확인

● Docker 로그                       실행 중 38분
  docker compose logs -f

◇ 로그인 화면 수정                 입력 대기 2분
  claude
  다음: 승인 후 테스트 실행

— 커밋 · 푸시                       최근 성공 12분
  git push
```

표시 우선순위는 `용도 → 다음 할 일 → 상태 → 최근 명령`이다. 경로와 세부 명령은 상세 화면에서 전체를 보여준다.

### 6.2 세션 상세

- 용도 이름 편집
- 다음 할 일 편집
- 프로젝트 표시 및 고정
- 현재·최근 명령 상태
- 최근 명령 5개와 종료 결과
- 터미널 앱과 세션 연결 상태
- `터미널로 이동` 버튼

명령 전문에는 토큰이나 비밀번호가 포함될 수 있다. 기본 저장과 화면 표시는 민감 인자를 제거한 요약을 사용한다.

### 6.3 정렬 원칙

- 프로젝트 그룹은 사용자가 마지막으로 정한 순서를 유지한다.
- 그룹 안에서는 사용자가 정한 순서 또는 터미널 창 순서를 유지한다.
- 상태가 바뀌었다는 이유로 행이 갑자기 이동하지 않는다.
- 주의가 필요한 세션은 배지와 필터로 모아본다.

## 7. MVP 기능 범위

### 필수 기능

- macOS Terminal 탭 발견
- iTerm2 세션 및 분할 pane 발견
- 프로젝트 경로와 Git 저장소 제안
- 세션 용도 이름 지정 및 유지
- 다음 할 일 한 줄 메모
- 입력 대기·실행 중 상태
- 검색 및 프로젝트 그룹
- 정확한 창·탭·pane으로 이동
- 앱 재실행 후 살아 있는 세션과 메타데이터 재연결
- 최근 닫힌 세션 표시
- 로컬 데이터 저장

### MVP 이후 후보

- Claude Code, Codex 등 AI 도구별 대기 상태
- 완료 알림과 알림 규칙
- 실행 포트 및 localhost 바로가기
- bash·fish 지원
- Ghostty·WezTerm·kitty 지원
- SSH와 tmux 안쪽 세션 지원
- 프로젝트별 터미널 템플릿
- 이름·메모 검색 기록

### MVP에서 하지 않는 것

- 자체 터미널 에뮬레이터
- 터미널 출력 전문 저장
- 명령 자동 실행, 재시작 또는 프로세스 종료
- 닫힌 세션의 프로세스 복구
- 클라우드 동기화와 계정
- 팀 공유와 협업
- AI로 명령 내용을 외부 서버에 전송하는 기능

## 8. 이름 제안 규칙

첫 버전은 외부 AI 없이 로컬 규칙으로 제안한다.

| 감지 예 | 제안 용도 |
|---|---|
| `npm run dev`, `vite`, `next dev` | 프론트 개발 서버 |
| `uvicorn`, `rails server`, `spring-boot:run` | API 서버 |
| `docker compose up`, `docker compose logs` | Docker 실행 / Docker 로그 |
| `tail -f`, 로그 뷰어 | 로그 확인 |
| `claude`, `codex`, 기타 알려진 CLI | AI 작업 |
| 반복적인 `git status`, `commit`, `push` | Git 작업 |

제안임을 시각적으로 구분하며 한 번 수정한 이름은 고정한다. 정확한 의미를 확신할 수 없으면 폴더명을 기본 표시하고 이름 입력을 강요하지 않는다.

## 9. 데이터 및 개인정보 원칙

- 모든 데이터는 기본적으로 Mac 안에 저장한다.
- 계정 가입을 요구하지 않는다.
- 터미널 출력과 스크롤백 전문은 수집하지 않는다.
- 명령 인자는 기본적으로 영구 저장하지 않는다.
- 알려진 민감 옵션, URL 사용자 정보, 환경 변수 할당은 제거한다.
- 사용자가 작성한 이름과 메모, 프로젝트 경로, 상태 이벤트만 필요한 기간 동안 저장한다.
- 진단 로그를 내보낼 때는 사용자가 내용을 확인할 수 있어야 한다.

## 10. 성공 기준

### 제품 사용성

- 8개 이상의 세션 중 지정한 작업을 찾는 시간이 기존 방식보다 중앙값 30% 이상 감소한다.
- 평가 과제에서 잘못된 터미널로 이동하는 일이 없어야 한다.
- 테스트 사용자 5명 중 4명이 도움 없이 첫 연결을 마친다.
- 테스트 사용자 5명 중 3명이 1주 뒤에도 자발적으로 사용한다.

### 신뢰성

- 지원 환경에서 세션 발견률 99% 이상
- 세션 클릭 후 정확한 대상으로 이동하는 성공률 99% 이상
- 상태를 확인할 수 없는 경우 잘못된 완료 상태 대신 `연결 확인 필요`를 표시

이 수치는 시장 조사 결과가 아니라 MVP 통과 여부를 판단하기 위한 목표다.

## 11. 검증 계획

### 문제 인터뷰

Terminal 또는 iTerm2 사용자 5명에게 현재 세션 관리 방식, 이름을 붙이는 습관, 상태를 놓친 경험, 다음 할 일을 기억하는 방식을 확인한다.

### 사용성 테스트

각 사용자에게 8~12개 세션이 열린 환경에서 다음 과제를 수행하게 한다.

1. 프론트 서버가 실행 중인 세션 찾기
2. 마지막 push 결과 찾기
3. Docker 로그 세션으로 이동하기
4. 다음 할 일이 적힌 AI 작업 세션 찾기
5. 다른 명령을 실행한 뒤에도 기존 용도의 세션 다시 찾기

기존 방식과 ShellCue 시안을 번갈아 사용해 시간, 오이동, 이름 수정 횟수, 상태 오해를 기록한다.

### 중단 또는 축소 기준

- 이름을 유지하는 일이 사용자에게 추가 관리 업무로 느껴진다.
- 자동 제안을 계속 수정해야 한다.
- 기본 Terminal/iTerm 기능보다 작업을 찾는 시간이 줄지 않는다.
- 상태 정확도가 낮아 사용자가 목록을 신뢰하지 않는다.

이 경우 전체 앱 범위를 확대하지 않고, 이름·메모·이동만 제공하는 작은 도구로 축소한다.

## 12. 경쟁 제품과 차별화 가설

| 제품/기능 | 강점 | ShellCue가 검증할 차이 |
|---|---|---|
| iTerm2 Cockpit / Session Status | iTerm 내부 상태와 이동 | Terminal과 iTerm을 한 목록에 표시하고 용도·다음 행동을 유지 |
| iTerm2 Session Notes / Tab Groups | 세션 메모와 그룹 | 메뉴 막대에서 모든 세션의 맥락을 빠르게 훑기 |
| SessionHub | iTerm 세션을 메뉴 막대에서 이동 | 프로젝트별 프로필 사전 설정 없이 발견하고 상태·메모 제공 |
| FocusForge, cmux | 정리된 자체 터미널 경험 | 기존 터미널을 바꾸지 않고 사용 |

차별화는 현재 가설이다. 실제 경쟁 앱 설치 비교와 사용자 테스트를 통과한 뒤 제품 주장으로 확정한다.
